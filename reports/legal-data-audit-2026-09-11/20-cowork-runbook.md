# دليل تشغيل المهمة عبر Cowork

**الغرض:** تسليم تنفيذي دقيق لما تعذّر في جلسة التدقيق السحابية.

---

## ١. لماذا Cowork هو الأداة الصحيحة

جلسة التدقيق السحابية عطّلها حاجزان — **وCowork على جهازك يرفعهما معًا:**

| الحاجز | في السحابة | في Cowork المحلي |
|---|---|---|
| المصادر الرسمية | ❌ محجوبة (`EGRESS_BLOCKED` حتى `example.com`) | ✅ شبكتك كاملة |
| بيانات اعتماد القواعد | ❌ غير موجودة | ✅ `.env` على جهازك |
| Neon / Supabase / Hostinger | ❌ تعذّر الاستعلام | ✅ اتصال مباشر |
| السكربتات والبوابات | ✅ جاهزة ومدفوعة | ✅ تُستنسخ وتعمل |

---

## ٢. ممنوعات — اقرأها قبل البدء

1. **ممنوع أن يكتب Cowork نصّ المواد بنفسه أو ينقلها يدويًا أو يولّدها من ذاكرة النموذج.**
   النص يُستخرج **آليًا من ملف المصدر الرسمي** (PDF/HTML) فقط. أي توليد نصّي
   يعيد إنتاج المشكلة نفسها التي نُصلحها — بل أسوأ، لأنه سيبدو رسميًا.
2. **ممنوع تشغيل `11-apply.sql` بلا موافقة بشرية صريحة.** كل السكربتات
   افتراضيّها `ROLLBACK`؛ لا تُبدَّل إلى `COMMIT` إلا بقرار معلن.
3. **ممنوع تشغيل أي كتابة قبل التأكد من الهدف.** البوابة المدمجة ترفض
   أي قاعدة غير `neondb`.
4. **ممنوع إعادة بناء أي فهرس قبل اعتماد Neon** — وإلا ثُبِّتت الإزاحة في فهرس جديد.

## ٣. الخطوات

### التحضير

```bash
git clone https://github.com/asim1417/hakeem-platform
cd hakeem-platform
git checkout claude/hakeem-legal-database-audit-rg7zx8
npm install
npx tsx scripts/test-arabic-ordinal.ts      # يجب: ✓ نجحت جميع الاختبارات (40)
```

### المرحلة أ — الجرد الحيّ (قراءة فقط، ابدأ بها)

```bash
npm run audit:db-env          # بصمة آمنة لكل بيئة — بلا أسرار
npm run audit:derived-drift   # الانجراف بين Neon والفهرس
```

**المتوقع من الثاني:** رصد ١٥ نظامًا غائبًا عن الفهرس (~١٬٤٢١ مادة).
إن ظهر رقم مختلف فالوضع تغيّر منذ 2026-09-11 — **أبلغ ولا تكمل**.

ثم شغّل `10-dry-run.sql` على Neon وسجّل مخرجات البنود ⑧ ⑨ ⑩
(نطاق الأثر، التضمينات، **عدد الدراسات المتأثرة** — وهو الرقم الغائب من التقرير).

### المرحلة ب — البيان الرسمي (الخطوة الحاجزة)

1. نزّل نظام المعاملات المدنية من **هيئة الخبراء بمجلس الوزراء** (`laws.boe.gov.sa`)،
   واحفظ الملف الأصلي كما هو في `data/official/` (للإسناد وبصمة المصدر).
2. استخرج المواد **آليًا** إلى JSON بالصيغة:
   ```json
   [{ "number": 1, "title": "المادة الأولى", "content": "…", "chapter": "…" }]
   ```
   العنوان يُنسخ حرفيًا من المصدر — **لا يُشتقّ من الرقم أبدًا**.
3. مرّره على بوابة الجودة:
   ```bash
   OFFICIAL_SOURCE_URL="<رابط المصدر>" \
   npx tsx scripts/audit/load-official-articles.ts data/official/civil.json \
     --emit-sql reports/legal-data-audit-2026-09-11/11a-load-official.sql
   ```

**البوابة ترفض** أي بيان فيه: عدد مخالف لـ٧٢١ · فجوة · رقم مكرر ·
**رقم لا يطابق عنوانه الترتيبي** · نصّ مكرر · نصّ فارغ.

> ✅ تحقّقت البوابة في الاتجاهين: رفضت بيانًا محاكيًا للخطأ الأصلي بـ٤٨٥ خطأ
> (خروج ١)، وقبلت بيانًا سليمًا (خروج ٠). **إن رفضت ملفك فالخلل في الاستخراج
> لا في البوابة — لا تُعطّلها.**

### المرحلة ج — التصحيح (بموافقة صريحة)

```
11a-load-official.sql   → تعبئة الجدول المرحلي
11-apply.sql            → راجع ناتج ⑨ (يجب: 721 / 1 / 0) ثم COMMIT
```
عند أي فشل: `12-rollback.sql`.

### المرحلة د — إعادة البناء (بعد اعتماد Neon فقط)

اتبع `13-rebuild-indexes.md` بالترتيب. وقبل الخطوة ٤ **أصلح**
`scripts/export-saudi-systems.ts:126` (ينقل العنوان لا يفبركه).

**مكسب فوري:** إعادة بناء الفهرس بـ`--from-db` تُعيد ١٬٤٢١ مادة إلى البحث.

### المرحلة هـ — التكرار وحالة السريان

`19-dedupe-and-supersede.sql`: شغّل القسم (أ) كاملًا، وأرفق ناتجه للمراجعة.
القسمان (ب) و(ج) — ترقية المخطط ووسم الملغى — **بموافقة**.

## ٤. ما لا يصلح له Cowork ولا أي وكيل

هذه تحتاج **محاميًا بشريًا**، ولا تُفوَّض:

- مراجعة كل دراسة استشهدت بالمدى ٢٣٧–٧٢١.
- الحكم على أزواج الأنظمة السبعة: أيّها ملغى فعلًا وبأي أداة وتاريخ.
- الأخطاء التفسيرية في دراسة العميل (م١٧٤ للقوة القاهرة، م٢٤٣ من الأحوال
  الشخصية لنقص الخصومة) — أخطاء **استدلال وتكييف** لا تُصلحها قاعدة بيانات.
- إقرار بوابة الدلالة (البوابة الرابعة).
