## 1. السبب الجذري للانزياح

الانزياح **ليس** خطأ parser في تقطيع المواد، بل **إسقاط مادة واحدة من المصدر** مع
اشتقاق رقم المادة من **التسلسل/الموضع** بدل العنوان الرسمي:

- المصدر `data/legal_articles_export.json` يحتوي **720** مادة للنظام (المتوقع 721).
- العدد الترتيبي المكتوب في العناوين فريد ويمتدّ 1..721 (بلا تكرار).
- عند اشتقاق الرقم من العنوان الرسمي، الفجوات الوحيدة هي: **[24، 237]**.
  - **237**: مفقودة فعليًّا — المادة الرسمية «إذا تعدد الدائنون في التزام غير قابل
    للانقسام» (نظير المادة 236 «إذا تعدد المدينون…») **غير موجودة في أي نسخة داخل
    المستودع** (لا في export، ولا في فهرس BM25، ولا في بيانات العدل).
  - **24**: ليست مفقودة — عنوانها **ملوّث** بمتن المادة (اندمج المتن داخل حقل
    `title`)، وحقل `content` يحمل عنوان فصل «الفصل الرابع: أنواع الحق»، فتعذّر تحليل
    عددها الترتيبي.
- لأن المادة 237 سقطت، انزاح كل ما بعدها: الرقم المتسلسل *N* يحمل عنوان المادة
  الرسمية *N+1* — إزاحة ثابتة (+1) من 238 إلى 721 (**484** مادة).

**الدليل:** أوّل تعارض عند الرقم المتسلسل 237 (عنوانه «الثامنة والثلاثون بعد المائتين»
= 238). الفحص `verify:civil-renumber` قبل الإصلاح: **492 إخفاقًا**.

### أين يقع الخطأ في الطبقة
- طبقة توليد `legal_articles_export.json` أسندت `article_number` بالتسلسل، لا من
  العنوان الرسمي. القيد `@@unique([lawName, articleNumber])` لا يكشف ذلك لأنه يمنع
  تكرار المفتاح فقط ولا يُثبت مطابقة الرقم للعنوان.
- الفرق بين قاعدة البحث (BM25) وقاعدة PostgreSQL: كلاهما مشتقّ من نفس المصدر
  المنقوص؛ لا يحتوي أيٌّ منهما نصّ المادة 237.

## 2. الإصلاح (مبدأ: تحقّق مادةً بمادة، بلا إزاحة عامة)

التصحيح الوحيد المطبَّق هو **اشتقاق رقم كل مادة من عنوانها الرسمي** (`parseArabicOrdinal`
على `title`) — تحققٌ مادةً بمادة من نصّ رسمي، **لا** إضافة ثابتة عمياء على ما بعد الكسر.

- `lib/modules/legal-core/article-numbering.ts` — دوال نقيّة: `deriveOfficialNumber`،
  `splitTitleFromBody`، `planRenumber`، `sha256Normalized`.
- `lib/modules/legal-core/article-upsert.ts` — إدخال idempotent مع:
  حفظ النسخة السابقة في `ArticleVersion` عند تغيّر النصّ؛ بوابة تمنع اعتماد تعديل من
  مصدر غير رسمي (يُرفع اقتراحًا في `ArticleAmendment` بحالة `needs_review`)؛ ختم
  provenance وبصمة SHA-256.
- `scripts/backfill/normalize-article-numbering.ts` — مُصحِّح staging (dry-run
  افتراضيًّا، `--apply`، داخل transaction، إعادة ترقيم آمنة على مرحلتين لتفادي تصادم
  القيد، **لا حذف**، الفجوات تُرفع للمراجعة).
- `scripts/backfill/rebuild-export-numbering.ts` — يصحّح `article_number` في المصدر
  حتى لا يعيد الـseed إدخال الانزياح.

### النتيجة بعد الإصلاح على staging
`verify:civil-renumber`: من **492 → 3 إخفاقات**، وكلّها **المادة 237 المفقودة فقط**:
```
العدد 720 ≠ 721
المادة 237 مفقودة
المرساة م(237) [تعدد الدائنين] لا تبدأ بـ«إذا تعدد الدائنون»
```
أي أن **الإزاحة (484 خطأ) زالت بالكامل**، ولم يتبقَّ إلا مادة واحدة تحتاج نصًّا رسميًّا.

## 7. خطوات التشغيل الآمنة على staging

```bash
npm ci
# 1) هجرة provenance الإضافية (staging فقط):
psql "$STAGING_DATABASE_URL" -f prisma/migrations/20260925040000_add_article_provenance/migration.sql
npm run db:generate
# 2) فحص قبل الإصلاح:
npm run verify:civil-renumber        # يُظهر الانزياح (~492)
# 3) معاينة الخطة (بلا كتابة):
npm run fix:numbering -- --system="نظام المعاملات المدنية"
# 4) تطبيق على staging داخل transaction:
npm run fix:numbering -- --system="نظام المعاملات المدنية" --apply
# 5) تصحيح المصدر لمنع العودة عند إعادة الـseed:
npm run rebuild:export-numbering -- --system="نظام المعاملات المدنية" --write
# 6) إعادة الفحص + تدقيق كل الأنظمة:
npm run verify:civil-renumber        # يتبقّى فقط نقص المادة 237
npm run audit:source-status
# 7) الاختبارات:
npm run test:numbering && npm run test:article-provenance && npm run test:arabic-ordinal
```

الأوامر المطلوبة في أمر التشغيل ونتائجها: راجع القسم «نتائج الاختبارات» أدناه.

## 8. خطة الاسترجاع (Rollback)

- **إعادة الترقيم**: العملية داخل transaction (كل شيء أو لا شيء). للتراجع بعد
  الالتزام على staging: أعِد الـseed من نسخة `git` سابقة للمصدر، أو استرجع لقطة
  قاعدة staging (snapshot) الملتقطة قبل التشغيل.
- **هجرة provenance**: إضافية فقط (أعمدة nullable). للتراجع:
  `ALTER TABLE "legal_articles" DROP COLUMN IF EXISTS ...` للأعمدة الستّة + إسقاط
  الفهرسين. لا فقدان لبيانات قائمة.
- **المصدر `legal_articles_export.json`**: التغيير في git؛ `git revert`/`git checkout`
  يعيده. لا حذف مواد (فقط إعادة ترقيم مشتقّة من العناوين).
- لا شيء من ذلك يمسّ الإنتاج؛ لا rollback إنتاجي مطلوب.
