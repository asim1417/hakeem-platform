# تقرير تشخيص عرض الأحكام القضائية — حكيم

**تاريخ الفحص:** 25 سبتمبر 2026  
**النطاق:** قاعدة Neon، واجهات حكيم العامة والداخلية، البحث، ومؤشرات الصحة.  
**طبيعة الفحص:** قراءة فقط؛ لم يُعدّل أي سجل أو إعداد أو نشر.

## النتيجة التنفيذية

الأحكام **ليست مفقودة من قاعدة Neon**. سبب عدم ظهورها للمستخدم هو مزيج من ثلاث مشكلات في طبقة التطبيق:

1. **عطل حرج في صفحة النظام العامة** يمنع الصفحة من العرض بالكامل (`BASE is not defined`).
2. **المكتبة العامة لا تحتوي أصلاً على واجهة لإظهار الأحكام**؛ فهي تجلب المواد فقط.
3. **مؤشر الصحة لا يعدّ الأحكام**، لذلك لا يظهر عددها رغم اتصال القاعدة.

توجد واجهة أحكام حقيقية داخل لوحة التحكم، لكنها تتطلب تسجيل دخول وصلاحية `LEGAL_CORE_VIEW`؛ لذلك لا يراها الزائر العام.

## الأدلة المؤكدة

| البند | النتيجة | الدليل |
|---|---|---|
| صفحة النظام العامة | فاشلة فعلياً | فُتحت صفحة «نظام الشركات» الحية، فظهرت شاشة «حدث خطأ غير متوقع». |
| سبب العطل | متغير `BASE` غير معرّف | سجلات Vercel: `ReferenceError: BASE is not defined` في `/legal/[slug]`، 1,032 ظهوراً حتى 23 سبتمبر 2026. |
| النسخة المتأثرة | هي نسخة الإنتاج الحالية | النشر `READY` على Vercel من `main`، والتزامه يحتوي المتغير غير المعرّف نفسه. |
| الواجهة العامة | لا تطلب أحكاماً | `app/legal/[slug]/page.tsx` يستعلم عن `legalArticle` فقط، ولا يستعلم عن `judicialCase` أو `legalArticleCaseLink`. |
| مستودع الأحكام | موجود ويعمل من القاعدة | `/dashboard/legal-core/judgments` يستعلم مباشرة من `prisma.judicialCase` ويعرض البحث والروابط. |
| الوصول للمستودع | محمي | فتح الرابط كزائر يعيد التوجيه إلى صفحة تسجيل الدخول، ثم يلزم إذن `LEGAL_CORE_VIEW`. |
| مؤشر الصحة | لا يقيس الأحكام | `health-index.ts` يعدّ الأنظمة والمواد والعلاقات وسجل التدقيق فقط؛ ولا يستدعي `prisma.judicialCase.count()`. |

## السبب الجذري الأول: انهيار صفحة النظام العامة

في `app/legal/[slug]/page.tsx` يُنشأ كائن SEO باسم `ld` بهذه الصيغة:

```ts
url: `${BASE}/legal/${encodeURIComponent(slug)}`
```

لكن الملف لا يعرّف `BASE`. وهو يستورد `getSiteUrl` بالفعل، لذا الإصلاح الصغير الصحيح هو تعريفه داخل الصفحة قبل إنشاء `ld`:

```ts
const BASE = getSiteUrl();
```

**الأثر:** لا تصل الصفحة إلى أي جزء من قائمة المواد أو أي محتوى يمكن أن يضيف إليه أحكاماً مرتبطة. هذا عطل عرض عام، وليس دليلاً على فقدان بيانات الأحكام.

## السبب الجذري الثاني: لا توجد واجهة أحكام عامة

حتى بعد إصلاح `BASE`، صفحة `/legal/[slug]` ستعرض:

- اسم النظام.
- عدد مواده.
- قائمة روابط المواد.

ولا تعرض:

- عدد الأحكام المرتبطة بالنظام أو المادة.
- قائمة الأحكام ذات الصلة.
- صفحة عامة للحكم.
- مرشحات المحكمة، المدينة، التاريخ، أو قوة الربط.

أما داخل لوحة التحكم فالمستودع موجود في:

`/dashboard/legal-core/judgments`

ويعرض البحث في العنوان والنص ورقم القضية/القرار، مع المحكمة والمدينة وروابط المواد. هذا يعني أن الوظيفة **مبنية داخلياً**، لكنها لم تُنقل إلى تجربة المستخدم العامة.

## السبب الثالث: الإحصاءات لا تشمل الأحكام

المسار العام `/api/health/index` لا يحسب جدول `judicial_cases`. لذلك عبارة «قاعدة البيانات متصلة» صحيحة، لكن لا يمكن استنتاج عدد الأحكام منها.

يوجد مسار إداري أفضل: `/api/admin/readiness`، ويحسب `judicialCases` فعلياً ويعرض حالة فهرسة الأحكام والمتجهات. لكنه محمي لصلاحية المدير الأعلى، وهذا صحيح أمنياً.

## حالة البيانات والبحث

- تقرير تشغيل سابق مباشر لقاعدة Neon سجل **51,105 حكماً** و**29,705 رابطاً** بين الحكم والمادة. هذا يؤكد أن استيراد الأحكام وصل إلى Neon في وقت الفحص.
- تقرير تفعيل البحث الدلالي بتاريخ 14 يوليو 2026 سجّل تغطية متجهات للأحكام قدرها **50,273 من 51,105 (98.4%)** في Neon.
- لا يصح اعتبار هذه الأرقام عدداً آنياً اليوم، لأن المسار العام لا يكشفه، ولم يُنفّذ استعلام مباشر مقيد بصلاحية القراءة إلى Neon في هذا الفحص.
- محرك الإجابات والبحث الشامل يدعم الأحكام: يستدعي البحث الهجين ثم يجلب `judicialCase`، كما يضيف الأحكام المرتبطة بالمواد من `legal_article_case_links`.

## مخاطر جودة يجب عدم تجاهلها

1. روابط الأحكام بالمواد موصوفة في الواجهة بأنها **آلية وتحتاج مراجعة قانونية قبل الاعتماد**. فلا ينبغي تقديمها للمستخدم على أنها سابقة ملزمة أو ربط نهائي بلا وسم واضح.
2. إتاحة نصوص الأحكام كاملة للعامة تحتاج سياسة عرض: بيانات الحكم المنشورة، إخفاء البيانات الشخصية إن وجدت، وإظهار المصدر والتاريخ والمحكمة وحالة المراجعة.
3. صفحة المستودع الداخلي تلتقط أخطاء الاستعلام أحياناً وتحوّلها إلى قوائم فارغة؛ الأفضل تسجيل الخطأ وإظهار حالة «تعذر البحث» بدلاً من إيحاء «لا توجد أحكام».
4. يوجد عطل منفصل في `/mcp` متعلق بقيمة دور `SUPER_ADMIN` وانتهاءات زمنية. لا يفسر انهيار صفحة الأنظمة، لكنه قد يعطل أدوات الإدارة أو الوكلاء ويجب فصله في معالجة مستقلة.

## خطة المعالجة الموصى بها

| الأولوية | الإجراء | النتيجة المطلوبة |
|---|---|---|
| P0 | إصلاح `BASE` وإضافة اختبار صفحة `/legal/[slug]` | عودة صفحات الأنظمة والمواد للعمل في الإنتاج. |
| P0 | نشر الإصلاح ثم فحص ثلاث صفحات أنظمة حية | التأكد من عدم ظهور شاشة الخطأ. |
| P1 | إضافة قسم «أحكام مرتبطة» داخل صفحة المادة، لا صفحة النظام فقط | إظهار أحكام مرتبطة فعلاً بالمادة مع المحكمة والتاريخ وحالة المراجعة. |
| P1 | إضافة صفحة حكم عامة مقيدة بسياسة العرض | رابط ثابت، مقتطف آمن، المصدر، والربط بالمواد؛ مع دخول للنص الكامل إذا اقتضت السياسة. |
| P1 | إبقاء مستودع الأحكام الكامل داخل لوحة التحكم أو خلف تسجيل الدخول | حماية المحتوى والبحث الكامل والتعامل المنضبط مع البيانات. |
| P2 | إضافة عداد أحكام إلى الصحة العامة: الإجمالي، المرتبط، غير المرتبط، وتغطية المتجهات | شفافية تشغيلية دون كشف نصوص الأحكام. |
| P2 | تشغيل فحص قراءة فقط من `/api/admin/readiness` | تثبيت العدد الحالي، حالة `rulingsSearchNorm`، وعدد متجهات الأحكام. |
| P3 | معالجة خطأ دور `SUPER_ADMIN` ووقت `/mcp` | استقرار أدوات الإدارة والوكلاء. |

## معايير قبول الإصلاح

1. صفحة نظام عام تفتح بلا خطأ وتعرض مواد النظام.
2. صفحة مادة تعرض حتى عدد محدد من الأحكام المرتبطة، مع «عرض المزيد» عند الحاجة.
3. الحكم المعروض يبيّن أنه مستورد/قيد المراجعة، ولا يقدّم الربط الآلي كحكم قانوني نهائي.
4. لوحة المدير تعرض العدد الحي للأحكام وحالة الفهرسة والمتجهات.
5. اختبار تلقائي يمنع إعادة ظهور `BASE is not defined` قبل أي نشر.

## خلاصة القرار

المشكلة ليست أن Neon بلا أحكام. المشكلة هي أن **الواجهة العامة تنهار أولاً، ثم لا تحتوي ثانياً على تصميم لعرض الأحكام**، بينما مؤشر الصحة لا يقيسها. يبدأ الإصلاح الصحيح بتصحيح صفحة النظام، ثم نقل عرض الأحكام المرتبطة إلى صفحة المادة ضمن ضوابط قانونية واضحة.
