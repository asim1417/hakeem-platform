## المتبقّي (يُستأنف بعد دمج #631) — بالترتيب

1. **الخطوة ٢ — المخطّط والهجرة:** أدرج `prisma/schema.additions.prisma` في `schema.prisma`؛ أضف الحقول الأربعة الاختياريّة إلى `DocumentUnit` (`uri/eId/contentHash/expressionId`) + `units DocumentUnit[]` في `LegalExpression`؛ ثم `prisma migrate dev --name legal-work-expression` (يحتاج `DATABASE_URL`) + `prisma validate` + `tsc`. **ممنوع** حذف عمود/جدول أو جعل حقلٍ قائمٍ إلزاميًّا.
2. **الخطوة ٤ — مواءمة السكربت والدفعة الجافّة:** طابق أسماء Prisma الفعليّة (استبدل `prisma.law`/`law.units`/`law.instrumentRef` الافتراضيّة)، ارفع وسم `@ts-nocheck`، ثم `--dry-run --limit=20`. **قف عند التقرير:** عدد الأنظمة المتعذّر استنتاج أداتها + عناوين المواد غير المقروءة.
3. **الخطوة ٥ — قرار التعبئة:** إن كان تعذّر الأداة **< ١٠٪** امضِ بدفعاتٍ من عشرين؛ إن كان **> ١٠٪** توقّف وأخرِج عيّنة عشرين حالة للمراجعة — **لا تُوسَّع أنماط `detectInstrument` تلقائيًّا** (التخمين في المعرّف الدائم خطأٌ لا يُصلَح).
4. **الخطوة ٦ — استعلام القبول:** `getArticleAsOf(workUri, articleNumber, hijriDate)` واختبارها على نظامٍ واحدٍ له تعبيرٌ واحد.
