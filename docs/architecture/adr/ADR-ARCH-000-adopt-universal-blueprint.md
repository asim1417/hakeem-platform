# ADR-ARCH-000 — تبنّي المخطط السيادي الشامل دستورًا معماريًّا + تجميد الأساس

- **الحالة:** مقبول
- **التاريخ:** 2026-07-31
- **النطاق:** المنصّة كاملةً (يتجاوز نطاق `docs/judicial-assistant/adr/*`)
- **المراجع:** [`UNIVERSAL_PLATFORM_BLUEPRINT.md`](../UNIVERSAL_PLATFORM_BLUEPRINT.md) ·
  [`BLUEPRINT_GAP_ANALYSIS.md`](../BLUEPRINT_GAP_ANALYSIS.md)

## السياق

قُدِّم «المخطط السيادي الشامل لبناء منصة حديثة» (38 قسمًا) بوصفه دستورًا معماريًّا عامًّا. المستودع
منصّة ناضجة (589 PR) تحقّق معظم النواة المعرفية وحوكمة الدليل فعليًّا. الطلب الصريح كان:
**«اقرأ النصّ كاملًا، ثم قيّم الفجوة، ثم طبّق ما لا يكسر شيئًا».** التقييم الآليّ الكامل موثّق في تحليل الفجوة.

## القرارات

1. **اعتماد المخطط مرجعًا حاكمًا، لا إعادة كتابة.** يُودَع المخطط في `docs/architecture/` أساسًا
   لمراجعة أي تغيير جوهريّ (§28) ولإعداد Roadmap/System Design (§38). لا يُلغي المخطط `CLAUDE.md`
   ولا `README.md`؛ بل يعلوهما كإطار تعميم.

2. **لا إعادة هيكلة الآن (التزامًا بـ§32 و§30/Stage 0).** الطبقات التي يتفوّق فيها حكيم على المخطط —
   حراس التأصيل (`lib/agent-runtime/enforcement/*`, `lib/modules/legal-chat/policy-gate.ts`)،
   نموذج المواد المُصدَّق (`ArticleVersion`, `ArticleAmendment`)، البحث الهجين، الأمن (SSRF/أسرار) —
   **تُجمَّد ولا تُلمس** بذريعة «المطابقة الشكلية للمخطط».

3. **معالجة الفجوات كعقود إضافية غير كاسرة فقط.** كل بند في جدول أولويات تحليل الفجوة (P1…P9) يُنفَّذ
   كـ PR مستقلّ **يضيف** كيانًا/عقدًا جديدًا أو حقلًا اختياريًّا بقيمة افتراضية، دون تعديل سلوك قائم أو
   توقيع دالّة عامّة. أي بند يتطلّب كسرًا (مثل P9 محرك الامتثال المُصدَّق) يُرفع لمجلس المراجعة (§28)
   بخطة ترحيل وتراجع قبل التنفيذ.

4. **Foundation Freeze (§29).** تُعتبر الأسطح التالية «أساسًا مُجمَّدًا» لا يُكسَر إلا بـ ADR جديد وخطة
   ترحيل: نموذج `prisma/schema.prisma` القائم، عقد `SearchProvider`، عقد `DocumentSourceConnector`،
   واجهة بوابة الذكاء (`callCentralProvider`/`completeWithConfig`)، خريطة RBAC (`role-permissions.ts`)،
   وسكِيما Manifest الوكلاء. التوسيع (إضافة حقول اختيارية/كيانات) مسموح؛ الكسر ممنوع.

5. **تفعيل تصنيف PR (§24) بحدّه الأدنى غير الكاسر.** يُضاف `.github/pull_request_template.md` يفرض
   **نوع PR** (ARCH/ENGINE/FEATURE/FIX/REFACTOR/TEST/DOCS/SECURITY/PERFORMANCE/BUILD/CI/CHORE)
   و**خطة تراجع**. لا يُضاف `CODEOWNERS` ولا حماية فروع في هذا الـ PR حتى لا يتغيّر سلوك الدمج الحاليّ.

## البدائل المرفوضة

- **توحيد Knowledge Object فورًا (§7):** يمسّ عشرات الجداول والمهاجرات = كسر واسع قبل نقطة استرداد. مرفوض (§32).
- **إدخال Command/Query/Event Bus كإعادة هيكلة شاملة:** يعيد كتابة كل `app/api/*`. البديل المقبول: Event
  Envelope إضافيّ (P1) يغلّف التدقيق القائم.
- **إضافة CODEOWNERS/حماية فروع الآن:** يغيّر تدفّق الدمج (قد يحجب PRs) = تغيير سلوكيّ. يؤجَّل بقرار صريح.

## الأثر

- **موجب:** مرجع حاكم موحّد + خارطة فجوات مسنودة بمسارات + بوابة حوكمة PR — كلّها DOCS/CI-config لا تلمس التشغيل.
- **محايد:** لا تغيّر في الكود التشغيليّ، ولا Prisma، ولا سلوك الدمج. `deploy-readiness-check` يبقى كما هو.
- **مؤجَّل (خارطة طريق):** P1–P9 في تحليل الفجوة، كلٌّ بـ PR ونوع من التصنيف الجديد.

## المراجعة

يُعاد النظر في هذا الـ ADR عند أوّل بند يتطلّب كسر «الأساس المُجمَّد» (بند 4)، أو عند إضافة أوّل حزمة مجال
غير قانونيّة (تفعيل §16 عمليًّا).
