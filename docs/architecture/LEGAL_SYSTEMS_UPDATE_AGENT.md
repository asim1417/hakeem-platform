# وكيل تحديث قاعدة الأنظمة — الخطة المعمارية وتحليل الفجوات

> وثيقة تصميم (لا كود). تُسقِط الأمر الموجّه لـ«وكيل تحديث قاعدة الأنظمة» على المخطط
> القائم فعلًا، وتُميّز ما يُعاد استخدامه ممّا يُضاف، وتقترح تصميم `document_units`
> وخطة الهجرة على مراحل مع بوّابات الحوكمة (§24 + ADR).
>
> الحالة: مقترح للمراجعة البشرية. لا يمسّ الأساس المُجمَّد قبل اعتماد ADR-ARCH-002.

---

## ٠. الخلاصة والقرار المعماري الواحد

المنصة تملك أصلًا **العمود الفقري الزمني** للنظام النظامي: نسخ المادة عبر الزمن،
تتبّع التعديلات، استخراج المرسوم، وديباجة مُخزَّنة. الناقص جوهريًّا شيئان:

1. **دقّة التمثيل** — النموذج الحالي «مسطَّح» (مادة واحدة = صف)، بينما الأمر الموجّه
   يطلب **شجرة وحدات من أول حرف حتى التوقيع** (أدوات الإصدار، الاستنادات، الأبواب،
   الفقرات الفرعية، أزواج التعريف). هذه فجوة تمثيل لا تُسدّ بتوسيع `legal_articles`.
2. **الالتقاط الحيّ** — لا خطّ التقاط من جريدة أم القرى (RSS) بعد.

**القرار الحاكم المقترح (يستلزم ADR-ARCH-002):**
إدخال جدول `document_units` **إضافةً غير كاسرة** يتعايش مع `legal_articles`، لا
يحلّ محلّها. تبقى `legal_articles` **وحدة الاسترجاع** في البحث والتضمين والاستشهاد
كما هي اليوم (صفر مساس)، ويصبح `document_units` **طبقة الأمانة الكاملة** (fidelity)
التي تحفظ الوثيقة حرفيًّا بشجرتها. الربط بينهما عبر `document_units.article_id`
(اختياري) لوحدات نوع `article`. فلا يتعطّل شيء قائم، ويُبنى الجديد فوقه تدريجيًّا.

هذا يحترم قاعدة الأساس المُجمَّد (ADR-ARCH-000 §4): **توسيع بإضافة كيانات جديدة، لا
كسر توافق**.

| الديباجة | `import-preambles.ts` → مادة رقمها 0 «الديباجة» (`article-ref.ts`) | رابعًا/ثامنًا: التمهيد — **لكن مسطَّحًا** (انظر §3) |
| استخراج المرسوم | `scripts/backfill-decrees.ts` + `lib/modules/legal-core/decree-extractor.ts` (`extractRoyalDecree`, `normalizeDigits`) | رابعًا-٤: استخراج أداة الإصدار ورقمها |
| نمط الالتقاط المُقفل | `import-moj-regs.ts` (بوّابة `CONFIRM_RUNTIME_DB_ALIGNMENT` + حارس Neon + upsert idempotent + `skipDuplicates`) | خامسًا: نمط الإدخال الآمن المُعاد استخدامه لأم القرى |
| مصدر تنظيمي قائم | `moj-fetch-regs.mjs` / `moj-fetch-instruments.mjs` / `import-moj-regs.ts` | مصدر ثانٍ (وزارة العدل) — بنية جلب+إدخال مرجعية |

| مُعرّف تشريعي ثابت | `LegalSystem.eliSlug` + `scripts/backfill-eli-slugs.ts` | أساس الإحالة الدائمة |

يتركّز في: نموذج الشجرة، القارئ الآلي، خطّ أم القرى، الاستكمال الرجعي، وفحص التقادم
المُنهَج.

## ٢. تحليل الفجوات (بندًا بندًا)

| بند الأمر الموجّه | الحالة | الإجراء المقترح |
|---|---|---|
| ثالثًا: مصادر (أم القرى RSS، بوابة هيئة الخبراء) | **مفقود** | خطّ التقاط جديد (P2) + موصِّل قراءة `laws.boe.gov.sa` |
| رابعًا: نموذج `document_units` الشجري | **مفقود** | جدول جديد + ADR-ARCH-002 (P1) |
| رابعًا: القارئ الآلي (آلة الحالات + المراسي) | **مفقود** | وحدة نقيّة `lib/modules/legal-core/document-parser/` (P1) قابلة للاختبار بمعزل |
| رابعًا-١: تحويل الأعداد اللفظية | جزئي (`normalizeDigits` للأرقام لا للأعداد اللفظية «الأولى→1») | قاموس أعداد لفظية جديد داخل القارئ |
| خامسًا: خطّ الالتقاط الجاري (guid، خام أولًا، تصنيف) | **مفقود** لأم القرى (النمط موجود لـ MoJ) | إعادة استخدام نمط `import-moj-regs` (P2) |
| سادسًا: علاقات `REPLACES/REPEALS/CITES` | **مفقود** في `RelationType` (يوجد `SUPERSEDES` و`AMENDS` الرسمي فقط) | توسيع enum إضافيًّا (لا كسر) (P1) |
| سادسًا: إسناد كل علاقة لموضعها الحرفي (اقتباس+guid) | جزئي (`LegalRelation.evidenceId`/`description`) | حقول إسناد صريحة على العلاقة (P1) |
| سابعًا: إدارة التعديل بالإصدارات | **موجود** (`ArticleVersion`) | تمديده لمستوى الوحدة لا المادة فقط (P3) |
| سابعًا-٣: حقل حالة إلزامي بالقيم الخمس | جزئي (`LegalArticle.status` نصّي حرّ) | enum حالة موحّد على الوحدة (P1) |
| سابعًا-٤: النفاذ المؤجل («لم يدخل حيز النفاذ») | **مفقود كحالة صريحة** | قيمة حالة + حساب تاريخ النفاذ من النشر (P2) |
| ثامنًا: الاستكمال الرجعي + حقل `completeness` | **مفقود** الحقل؛ `import-preambles` يغطّي الديباجة جزئيًّا | حقل `completeness` على `LegalSystem` + تقرير تقدّم (P2) |
| تاسعًا: فحص التقادم الدوري مقابل البوابة | **مفقود** | مهمة مجدولة + وسم `متقادم-قيد التحقق` (P4) |
| عاشرًا: بوّابات الرفع للمراجعة البشرية | جزئي (`reviewStatus` منتشر) | طابور مراجعة موحّد يقرأ من الوحدات/العلاقات (P3) |

## ٣. تصميم `document_units` (المقترح للـ ADR)

جدول واحد يخزّن شجرة كل وثيقة (بمطابقة حقول الأمر الموجّه، رابعًا-٢):

```
document_units
  id            uuid pk
  system_id     fk → legal_systems.id        // ربط الحزمة كلها بسجل نظام واحد
  document_id   text        // معرّف الوثيقة داخل الحزمة (نص/قرار/مرسوم/لائحة)
  parent_id     fk → document_units.id (self, nullable)
  unit_type     enum        // انظر أدناه
  ordinal       int         // ترتيب القراءة داخل الوثيقة (شرط تحقّق إعادة التركيب)
  label_ar      text        // التسمية كما وردت
  number        text?       // الرقم المعياري ("12"، ومكرر = "12.1")
  text_raw      text        // الحرفي بلا مساس (حجّة)
  text_normalized text?     // مطبَّع للفهرسة (بلا RLM/LRM)
  path          text        // مسار مادي: doc/part:1/chapter:2/article:12/para:3
  char_start    int?
  char_end      int?
  status        enum DocUnitStatus
  valid_from    timestamptz?
  valid_to      timestamptz?   // null = النافذ حاليًا
  source_guid   text?          // guid عنصر أم القرى
  source_url    text?
  article_id    fk → legal_articles.id (nullable)  // جسر لوحدات نوع article
  created_at / updated_at
  @@index([system_id]) @@index([document_id, ordinal])
  @@index([parent_id]) @@index([unit_type]) @@index([status])
```

**enum `DocUnitType`** (رابعًا-٣): `instrument_opening, recital, instrument_clause,
instrument_closing, signature, system_preamble, part, chapter, section, article,
paragraph, subparagraph, definition_item, unclassified`.

**enum `DocUnitStatus`** (سابعًا-٣، القيم الخمس): `IN_FORCE (نافذ)، AMENDED (معدَّل)،
REPEALED (ملغى)، NOT_YET_IN_FORCE (لم يدخل حيز النفاذ)، STALE_UNVERIFIED
(متقادم-قيد التحقق)`.

**قاعدة عدم السقوط + التحقق الختامي** (رابعًا-٨): كل مقطع بلا مرساة → وحدة
`unclassified` + رفع للمراجعة؛ واختبار لا‑تراجعي: `concat(text_raw ORDER BY ordinal)
== النص الأصلي حرفيًّا` لكل وثيقة.

### لماذا جدول جديد لا توسيع `legal_articles`؟
- `legal_articles` وحدة استرجاع مسطّحة و**جزء من الأساس المُجمَّد**؛ توسيعها بشجرة
  يكسر كل `findMany` بلا `select` على قاعدة لم تُهاجَر (نفس تحذير حقول `norm_*`
  في `schema.prisma`).
- التعايش يُبقي الديباجة الحالية (مادة 0) تعمل، ثم تُهاجَر تدريجيًّا إلى
  `instrument_opening/recital/…` دون توقّف الخدمة.
- الإحالة الدقيقة للفقرة الفرعية (حارس الإحالات) تحتاج مرساة بمسار `path` — غير
  ممكنة على مستوى المادة المسطّحة.

## ٤. خارطة الطريق على مراحل (بوّابات الحوكمة)

| المرحلة | المخرَج | يمسّ الأساس؟ | البوّابة |
|---|---|---|---|
| **P0** | هذه الوثيقة + ADR-ARCH-002 (قرار `document_units`) | لا | مراجعة بشرية للـ ADR |
| **P1** | القارئ الآلي (وحدة نقيّة، اختبارات ذهبية على أنظمة عيّنة) + هجرة `document_units` + توسيع `RelationType` (إضافة `REPLACES/REPEALS/CITES`) | نعم (إضافة) | ADR-ARCH-002 + migration file + §25 (typecheck/build/tests) |
| **P2** | خطّ التقاط أم القرى (خام أولًا + guid + تصنيف)، حساب النفاذ المؤجل، حقل `completeness`، استكمال الديباجات/الأدوات رجعيًّا | نعم (حقول إضافية) | نمط `CONFIRM_RUNTIME_DB_ALIGNMENT` + dry-run افتراضي |
| **P3** | الإصدار على مستوى الوحدة، طابور مراجعة موحّد، الدمج ومقارنة بوابة هيئة الخبراء | نعم | مراجعة بشرية للدمج |
| **P4** | فحص التقادم المجدول + الوسم الظاهر للمستخدم + حارس الإحالات على الوحدات | لا (قراءة/وسم) | مهمة مجدولة (Routine) |

كل مرحلة **PR واحد صغير** (§24)، ولا تبدأ المرحلة التالية قبل خضرة فحوص السابقة.

## ٥. قيود التشغيل والشبكة (صريحة)

- **الجلب الحيّ محجوب في هذه الجلسة**: سياسة الخروج (egress) تحجب مضيفات مثل
  `hakeem-platform.vercel.app` (رأيناه 403)، والأرجح أن `uqn.gov.sa` و

  (GitHub Actions مجدول / بيئة إنتاج)، لا من داخل الجلسة. القارئ الآلي (P1) و
  الهجرات لا تحتاج شبكة ويمكن بناؤها واختبارها هنا بالكامل.
- **الكتابة على القاعدة** تبقى خلف بوّابة `CONFIRM_RUNTIME_DB_ALIGNMENT` + حارس Neon
  (كما في `import-moj-regs`/`derive-article-versions`)، ودائمًا dry-run افتراضيًّا.

## ٦. أثر الأساس المُجمَّد و ADR المطلوبة

- **ADR-ARCH-002 (مطلوب قبل أي كود P1):** اعتماد `document_units` كطبقة أمانة
  متعايشة، وتوسيع `RelationType`. كلاهما **إضافة** (لا كسر)، لكن لأنه يمسّ نموذج
  البيانات القانوني يلزم قرار مُوثَّق ومجلس مراجعة (§28) حسب قالب PR.
- لا تُعدَّل `legal_articles` بنيويًّا. الديباجة الحالية (مادة 0) تبقى حتى تُهاجَر.
- كل واقعة تعديل/إلغاء تُسنَد لمصدر رسمي (عاشرًا-١) — لا وسم آليّ بلا سند.

## ٧. أسئلة مفتوحة للمراجعة البشرية

1. **حدود الحزمة:** هل يُخزَّن القرار والمرسوم كوثيقتين مستقلتين داخل `document_units`
   (بنودهما أحكام ملزمة) أم تُلخَّص إحالتهما فقط؟ (الأمر الموجّه يرجّح الأول.)
2. **ترحيل الديباجة الحالية** (مادة 0) إلى وحدات الأداة: دفعة واحدة أم بالتوازي؟
3. **تعارض المصدرين** (أم القرى ↔ هيئة الخبراء): تأكيد أن الترجيح **بشري دائمًا** بلا
   حسم آليّ (خامسًا/عاشرًا).
4. **مصدر تاريخ آخر تعديل** لفحص التقادم: هل بوابة هيئة الخبراء تعرضه بصيغة قابلة
   للقراءة الآلية المستقرة، أم يحتاج القارئ صفحة كل نظام؟
