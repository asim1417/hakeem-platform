## الخطوة 2 — توحيد مصدر النص (الأولوية)

القاعدة: النص المعروض في أي مكان = `textAsOf(content, unitVersions, asOf ?? now)` من `lib/modules/legal-core/verified-status.ts`.
لا قراءة مباشرة لـ `legal_articles.content` لعرض نص سارٍ.

المواضع المعروفة:

| الموضع | الملف |
|---|---|
| وصف الصفحة وJSON-LD | `app/legal/[slug]/[article]/page.tsx` (`generateMetadata` و`jsonLd.text`) |
| صفحة النظام | `app/legal/[slug]/page.tsx` (تحقّق أنها تستعمل `unitVersionsFor`) |
| أدوات الوكيل | `lib/modules/agents/tools/index.ts` (تقرأ `article_versions` و`content`) |
| مسارات الوكيل | `lib/modules/agents/**` كل ما يقرأ `.content` لمادة |
| سيرفر MCP | `app/mcp/route.ts` و`lib/mcp/tools/*` (`hakeem_get_article`، `get_articles_range`، `search`) |
| واجهات API | `app/api/legal*`، `app/api/legal-search`، `app/api/legal-rag` |

المطلوب:
1. دالة واحدة في `lib/modules/legal-core` مثل `effectiveArticleText(articleIds[], asOf?)` تجمع النسخ دفعة واحدة (`unitVersionsFor`) وتعيد النص الساري وتاريخه وسنده.
2. استبدال كل قراءة عرض للنص بها.
3. المادة الملغاة (`verification` بحالة `ملغاة`) لا تُعرض نصًّا ساريًا: تُرجع حالة الإلغاء وسندها.
4. `article_versions` (16,007 صف قديم) لا تُستعمل مصدرًا للنص الساري. أبقها للقراءة التاريخية فقط إلى أن يقرر المالك.
5. اختبار وحدة لكل مستهلك: نظام العمل م5 يُرجع نص م/46 لسنة 1436هـ، ومادة ملغاة تُرجع الإلغاء.

## الخطوة 3 — عرض الحالة

1. صفحة النظام تعرض حالته من `verification` (ساري / ملغى) مع السند.
2. النظام الملغى: شريط إلغاء أعلى الصفحة + رابط البديل إن وُجد، ولا يُعرض كأنه ساري.
3. البحث يستبعد الأنظمة الملغاة افتراضيًّا، مع خيار «إظهار الملغى».
4. عبارة «الحالة قيد التحقق» لا تظهر على مادة لها نسخة موثّقة في `unit_version`: تُعرض «معدّلة بموجب … من تاريخ …».
